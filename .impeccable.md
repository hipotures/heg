## Design Context

### Users

The primary user is a solo structural-graph researcher and campaign operator.
They use the interface to monitor bounded search, understand Director
decisions and measured effects, inspect scientific evidence, compare model
configurations, and decide what should happen next without confusing software
state with a mathematical claim.

### Brand Personality

Precise, calm, scientific. The interface should create confidence through
clear provenance, restrained visual hierarchy, explicit state labels, and
legible technical detail.

### Aesthetic Direction

Editorial laboratory notebook: information-dense but composed, with semantic
tables, readable narrative summaries, disciplined typography, and selective
technical monospace. Both light and dark themes are first-class. The user can
switch themes, and the choice is remembered in browser local storage. Avoid
neon developer-dashboard styling, decorative gradients, glass effects,
generic card grids, and raw JSON as the primary presentation.

### Design Principles

1. Lead with scientific meaning; keep raw evidence one deliberate disclosure
   away.
2. Make status, validity, provenance, and uncertainty explicit in text, never
   by color alone.
3. Support dense expert workflows with compact rows, bounded lists, stable
   hierarchy, and strong wrapping behavior.
4. Treat desktop, tablet, and narrow mobile widths as distinct layouts rather
   than scaled copies.
5. Keep the implementation inspectable: semantic HTML, CSS tokens, plain
   JavaScript, no frontend framework or build step.
